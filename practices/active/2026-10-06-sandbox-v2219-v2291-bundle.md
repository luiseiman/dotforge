## Description
- `sandbox.network.strictAllowlist` (v2.1.219): deny non-allowlisted hosts without prompting. Per-command `allowed_domains` for Bash/PowerShell/Monitor in auto mode (v2.1.271). Trailing-dot host in `deniedDomains` now blocks (v2.1.282).
- `sandbox.credentials` schema expanded (v2.1.221/224/232): `extract` + `onExtractNoMatch`; `decode: "jwt"` + `maskClaims`; `awsPairs` / `sigv4`; requires `network.tlsTerminate`; honored only from user/managed/`--settings`. File `mode: "mask"` works on **Linux/WSL only** — macOS falls back to `deny`. GitLab token redaction; `glab` config store protected like `gh`.
- Deny-path fixes: trailing-slash entries (`denyRead: "~/.aws/"`) were silently bypassable (v2.1.224); macOS wildcard read-deny (`**/.env`) now takes precedence and survives renames (v2.1.236); `--setting-sources` honored by sandbox filesystem config (v2.1.246); violation details appear in Bash results (v2.1.224/243); sandboxed commands can write to project dirs named `hooks/`/`config/` (v2.1.275).
- `!` bash-mode commands run outside the sandbox even in strict mode (v2.1.260); `allowUnsandboxedCommands:false` still disables model's `dangerouslyDisableSandbox`. Sandboxed heredocs / `python3 -c` no longer prompt every run under auto-allow (v2.1.283). `sandbox.ripgrep`, `bwrapPath`, `socatPath` user/managed-only.
- v2.1.251 security fixes: symlink swapped after permission check; Grep/Glob not applying `Read(...)` deny through symlinked paths; marketplace plugin command outside plugin dir; project settings enabling beta tracing / raw API body logging; Workflow `scriptPath` read before permission check.

## Evidence
`sandboxing.md:19` documents `credentials` as `files`/`envVars` with `mode: mask|deny` + `extract` only, no platform caveat — production-tier recommendation ("prefer mask") is wrong on macOS (Luis's primary machine). 0 hits for `strictAllowlist`, `tlsTerminate`, `sandbox.ripgrep`.
